# Team Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Teams row in the desktop sidebar leading to the league's table and a page per team that shows its season: what stands out, how it plays at both ends, who does what, its games and which of them the coach has.

**Architecture:** Pure readings in `packages/shared/lib` turn the season payload, the fixture list, the roster and the league's player page into plain data (a league-wide season, keys, a schedule, players). Desktop hooks read the two answers the `genius` function already serves and hand that data to two pages that only draw it. The backend changes by two fields on a trimmed fixture.

**Tech Stack:** TypeScript, React 19, Tauri 2 (the macOS menu is Rust), vitest, Playwright headless, one Supabase edge function (Deno).

**Spec:** `docs/superpowers/specs/2026-11-21-team-page-design.md`. Read it first; its copy tables and mock-ups are binding.

## Global Constraints

- Before any UI step, invoke the `apple-design` skill; before writing any string the spec doesn't give, invoke the `copywriting` skill (CLAUDE.md).
- One formula: every factor is `factorsOf` over `geniusTotals` (`game-box.ts`, `season-context.ts`). No second definition.
- Only regular-season games with both teams' rows count (`counted` in `season-context.ts`).
- A team is measured within its group (the standings' `poolNumber`): places, averages, keys. 1 is best; ties share a place. The single-game swing is competition-wide.
- Constants, exactly: `MIN_KEY_GAMES = 5` (also the floor for showing places), `KEY_EDGE = 2`, `KEY_ERRORS = 2`, `MAX_KEYS = 3`, three-point share scale `0.6`, `WHO_MIN_GAMES = 3`, `WHO_MIN_FTA = 20`, `LEADER_MIN_3PA` (20, existing), `FORM_MARGIN_CAP = 20`; first 8 players, first 5 played games, next 2 games still to play.
- Shooting (eFG%) and the free-throw rate are never a key.
- Season numbers open nothing and are not buttons. No colour says good or bad. Hover, pressed and selected rows use the neutral fills; the accent is for controls only.
- Copy is English, sentence case, exactly as the spec writes it.
- Motion as the Stats view: "Show all" expands in place with the app's standard spring and cross-fades under reduced motion; rows highlight on press; the toolbar's material comes from the `Page` and `Toolbar` pair.
- What a page section draws from is plain JSON-serialisable data made in `packages/shared` (step 3 will store it in a report).
- Desktop only. No migration. No new Genius calls. The function changes only in `trimFixture`.
- The repository is public: fixtures hold made-up names or public league numbers, never secrets.
- Never push, and never deploy to production. The staging deploy in Task 11 needs Leonard's go-ahead.

## Review Focus

1. A team with a standings row but no counted game (new, withdrawn, early season): no `NaN`, no places, the early line. Pinned in Tasks 1 and 3.
2. A cancelled fixture, or one still "scheduled" long after its date: never listed as still to play, never in the season strip. Pinned in Task 4.
3. The two caches disagree: a finished fixture without totals yet. The row shows its score and no per-possession numbers. Pinned in Task 4.
4. The space has no team, or its team isn't in this competition: no "Your next game", no "Your team" or "You" marks, no meeting line. Pinned in Tasks 4 and 6.
5. A finished fixture with an empty or non-numeric score (a walkover): no "0–0", no result, not in the strip. Pinned in Task 4.

  ```ts
  export const PROFILE_KEYS: readonly ProfileKey[]; // ppp, efg, tovRate, orebPct, ftRate, threeRate, pace
  export const PROFILE_SCALE: Record<Exclude<ProfileKey, "pace">, number>; // FACTOR_SCALE + threeRate: 0.6
  export type End = "own" | "allowed";
  export interface TeamProfile {
    teamId: number;
    group: number | null;            // standings poolNumber of the row standingOf picks; null without standings
    games: number;                   // counted regular-season games
    own: Record<ProfileKey, number | null>;
    allowed: Record<ProfileKey, number | null>;   // allowed.pace is always null
    place: Record<End, Record<ProfileKey, number | null>>;
    of: number;                      // teams of its group with a counted game
    perGame: Record<PointsFrom, number | null>;
    standing: TeamStanding | null;
  }
  export interface GroupSeason { group: number | null; teamIds: number[]; mean: Record<End, Record<ProfileKey, number | null>> }
  export interface LeagueSeason {
    teams: ReadonlyMap<number, TeamProfile>;     // every team in the standings or in a fixture
    groups: GroupSeason[];                        // ascending group number, null last
    swing: Record<End, Record<ProfileKey, number | null>>;
  }
  export function leagueSeason(payload: SeasonPayload): LeagueSeason;
  ```
  `threeRate` is 3PA ÷ FGA of the summed totals; `pace` is possessions (`factorsOf`) ÷ games. Places: own, 1 = highest, except `tovRate` 1 = lowest; allowed, 1 = lowest, except `tovRate` 1 = highest. `mean` is the mean of the group's team values. `swing` is `leagueSwing`'s method (per team with `MIN_SWING_GAMES`, the population SD of single-game values, then the mean over teams), over every `ProfileKey`, for a team's own games and for its opponents' (allowed).

- Produces:
  ```ts
  export const MIN_KEY_GAMES = 5, KEY_EDGE = 2, KEY_ERRORS = 2, MAX_KEYS = 3;
  export type KeyMetric = "ppp" | "threeRate" | "orebPct" | "tovRate" | "pace";
  export interface TeamKey { end: End; metric: KeyMetric; high: boolean; value: number; place: number; of: number; score: number }
  export interface TeamKeys { status: "early" | "ready"; games: number; withBall: TeamKey[]; withoutBall: TeamKey[] }
  export function teamKeys(profile: TeamProfile, league: LeagueSeason): TeamKeys;
  /** `where` is the group's name in a grouped league, else null ("the league"). */
  export function keySentence(key: TeamKey, where: string | null): string;
  export function keysEmptyLine(keys: TeamKeys): string | null;
  ```
  Candidates: own `ppp`, `threeRate`, `orebPct`, `tovRate`, `pace`; allowed `ppp`, `threeRate`, `orebPct`, `tovRate`. A candidate is a key when `profile.games >= MIN_KEY_GAMES`, its place is `<= KEY_EDGE` or `> of - KEY_EDGE`, and `gap >= KEY_ERRORS * se` where `gap = |value - group mean|` (must be `> 0`) and `se = swing / sqrt(games)`. `score = se > 0 ? gap / se : Infinity`; a null swing or mean is no key. Highest score first, at most `MAX_KEYS` a side. `high` is `value > mean`.
  The place in a sentence: the group's highest value reads "most in {where}", its lowest "fewest in {where}", anything else `"{ordinal(place)} of {of}"`; `{where}` is "the league" or the group's name.
