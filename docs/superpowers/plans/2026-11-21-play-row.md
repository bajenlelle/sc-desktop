# One play row Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One 32 px, one-line play row shared by Teams Plays, the game view, Add clips and the playlist editor: clock · team code · event dot and word · player with labels · context · score · marks · actions.

**Architecture:** A presentational module `apps/desktop/src/components/plays/play-row.tsx` draws the row's cells and its two actions; each list keeps its own row root (Teams and the game view a pressable `div`, Add clips a `role="row"` div, the editor the drag-and-menu `role="row"` div) and passes what differs through props and slots. One pure helper (`teamCode`) goes in `packages/shared` with tests. Lists move over one per task, each with its headless specs.

**Tech Stack:** React 19, TypeScript, Tailwind v4 (container queries), framer-motion, Radix context menu, Playwright headless (WebKit and Chrome), vitest.

**Spec:** `docs/superpowers/specs/2026-11-21-play-row-design.md` (approved by Leonard 2026-11-21). Read it before any task.

## Global Constraints

- Row height exactly **32 px** for every play row, whatever it holds (`PLAY_ROW_HEIGHT`); Teams and Add clips window their lists by it. The editor's text and stats card rows keep their own layout and height.
- Column order: Lead · Now (12 px) · Clock · Team (about 36 px, game view with both teams only) · Event (about 104 px, left-aligned, 7 px dot + `eventLabel` in grey) · Player and labels (flex; name truncates first) · Context (grey, truncates) · Score (40 px, right-aligned, game view only) · Marks (editor only) · Actions (2 × 24 px, space always reserved).
- Clock text: `playClock(e)` ("Q1 09:47") in Teams, Add clips and the editor; `formatGameClock` alone ("09:47") under the game view's quarter headers; no game clock → the quarter alone.
- Labels on rows: up to 2, then "+n" with the rest in a tooltip; the quiet chip (neutral `bg-fill-2` pill, 7 px dot in the label's colour, name in `text-muted-foreground`, 11 px). Other places keep today's `LabelChip`.
- Event dot colours: one `EventHue` → class map; families match today's strips (make emerald, miss red, rebound blue, assist cyan, steal and block violet, turnover amber, foul orange, neutral slate). Shot value no longer deepens the colour.
- States: hover = `hover:bg-fill-1`; play on screen = `ActiveRowPill` + ▶ in Now + name `font-medium`; selected = `bg-row-selected`; in target = grey ✓ always shown. A play added from this view (`added`) gets a ✓ that arrives in `text-primary` with `springs.snappy`, settles to grey, and removes on click ("In {target}. Remove"); a play that was already in (`in`) has a static ✓ ("Already in {target}"), as the game view does today; can't play = the text cells dimmed (`opacity-55`), actions and ✓ at full contrast; keyboard focus = the inset ring.
- Actions (Label, +) show on hover, on the current row, on the keyboard-focused row and while their picker or the row's menu is open (`REVEAL`); hidden by opacity only, never by removing them from layout.
- The accent (`text-primary`, `bg-primary`) appears on a row only for the fresh-add ✓ and the ▶ is foreground, not accent.
- Accessible names stay as today: "Add to {target}" / "Add to a playlist", "In {target}. Remove", "Already in {target}", "Label this play" (game view and Teams), `title="Labels"` on Add clips' tag, checkbox "Select". Tooltips add the key: "Add to {target}" with `A`, "Label" with `G`.
- Narrow rows give way in this order (container query on the row): below about 480 px labels show as dots only; below about 400 px the event shrinks to its dot (word in the tooltip) and the clock drops its quarter where headers carry it; then the name truncates. Actions, ✓ and dots never go. Builder measures the exact breakpoints.
- Game view team code: drawn only when `filters.team === 0`; `teamCode(e)`; a play with no team leaves the slot empty.
- Teams: an action from a row's Label button or menu acts on the selection if that row is in it, else on that row alone; keys keep acting on the selection, else the play on screen.
- Add clips: no + and no new menu; ✓ replaces the 40 % dimming; adding stays ticks and ⌘↩.
- Copy: English, sentence case. UI rules: run the `scoutable:apple-design` and `scoutable:copywriting` skills before UI work (CLAUDE.md).
- Tests: targeted headless specs per task in **one browser (WebKit)**; both browsers and the full suite once, in Task 6 (memory: lean test routine).

## Review Focus

1. A long name with three labels in Teams at its narrowest (1024 × 720 window, sidebar shown): nothing wraps or overflows, actions and ✓ stay, the row gives way in the stated order. Test in Task 2.
2. The game view with both teams listed: every play with a team shows its code; filtering one team removes the column. Test in Task 3.
3. Hovering a row or adding a play never moves the row's text (actions keep their space). Test in Task 2 (bounding box of the name before and after hover and after A).
4. Keyboard only: the focused or current row shows Label and +; Shift+F10 opens the row menu in Teams. Test in Task 2.
5. The editor: dragging a play row and a group still lands in the right place, and a checkbox click selects rather than plays. Test in Task 5.
